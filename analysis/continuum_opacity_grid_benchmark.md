# Continuum-opacity wavelength-grid benchmark

Date: 2026-09-21  
Branch: `codex/cdr-physical-range-selection`  
Status: benchmark/prototype only; the temporary native cache was removed after measurement. No production API was added.

## 1. Problem

`LINEOPAC` and the radiative-transfer matrices evaluate continuum opacity at very many line or synthesis wavelengths. The experiment asked whether a coarse wavelength cache can replace roughly one million exact `CONTOP` evaluations during CDR precomputation without materially changing `ALMAX`, central depth, physical line ranges, line selection, or the normalized spectrum.

The answer is **yes for the core idea, but not as an unguarded uniform-grid implementation**. A 1 Å linear cache reduces a 378,154-line CDR job from 91–101 s to 3.9–4.2 s and gives excellent spectrum-level accuracy in the tested windows. A uniform grid must not interpolate across physical edges, and merely inserting edge endpoints is still insufficient in the steep Mg I region near 3756.608 Å. Production code should use a 1 Å base grid plus exact/adaptive guard regions.

## 2. Current `CONTOP` usage and duplicated work

Relevant current locations in `smelib/src/sme/sme_synth_faster.cpp` are:

- `CONTOP`: line 2525.
- `CONTOP_COMPONENTS`: line 2555.
- `ALAM`, which fills all opacity contributors: line 2611.
- `CentralDepth`: line 7556; it calls `CENTERINTG` at line 7675.
- `CENTERINTG`: line 9303; it reaches `OPMTRX1`.
- `LINEOPAC`: line 9393; exact `CONTOP` is called at the line center.
- `OPMTRX`: line 9719; exact `CONTOP` is called at every transfer wavelength.
- `OPMTRX1`: line 10051; exact `CONTOP` is called at the line center.

The formerly redundant outer `CentralDepth -> CONTOP` call has already been removed on this working branch. Therefore the exact baseline in this report is the improved current path, not the older ~120 s baseline. Even after that removal, a CDR run makes about 1.13–1.14 million continuum queries: approximately one pass through `LINEOPAC`, another through `OPMTRX1`/`CentralDepth`, plus transfer-grid work.

## 3. Cacheability audit

For a fixed loaded SMElib state, continuum opacity is a deterministic function of wavelength and depth. Its state dependencies are:

- model geometry and depth grid: `MOTYPE`, `NRHOX`, `RHOX`, `T`, `RHO`, `XNE`, `XNA`, `RADIUS`, `RAD_ATMO`;
- abundance/EOS/ionization results: `FRACT`, partition functions, species indices, and electron/particle densities;
- opacity switches `IFOP`;
- wavelength-derived globals `FREQ`, `FREQLG`, `EHVKT`, `STIM`, and `BNU`.

The global state and component accumulators are declared around lines 121–207. `CONTOP` sets the wavelength-derived globals, then `ALAM` overwrites the depth-dependent component arrays `AHYD`, `AH2P`, `AHMIN`, `SIGH`, `AHE1`, `AHE2`, `AHEMIN`, `SIGHE`, `ACOOL`, `ALUKE`, `AHOT`, `SIGEL`, and `SIGH2` before returning total extinction.

This makes the result cacheable only with correct invalidation after any model, abundance, EOS/ionization, opacity-switch, or geometry change. The present implementation is stateful and non-reentrant; a production cache must be owned by one SMElib/DLL state and follow the thread-safety work rather than use a process-global mutable map.

### Quantities that can be cached

- `chi`: total continuum extinction, used by `LINEOPAC`, `OPMTRX`, and `OPMTRX1`.
- `kappa`: true absorption, from `ContinuumTrueAbsorption` at line 194.
- `sigma`: coherent scattering, from `ContinuumCoherentScattering` at line 200.

All are arrays of length `NRHOX`, not scalars. Caching only one scalar opacity is incorrect.

### Source/scattering caveat

The default benchmark has `continuum_scattering_source_mode=0`. In that mode `OPMTRX` and `OPMTRX1` compute the Planck source analytically and use cached/exact total extinction.

When scattering-source mode is enabled, `CONTINUUM_SCATTERING_SOURCE` (line 2584) calls `CONTOP_COMPONENTS`, constructs Planck values, and solves a depth-coupled moment equation. A production design should cache `kappa`, `sigma`, and `chi` separately and either solve the scattering source at the requested wavelength or separately validate interpolation of the solved `J`/source arrays. Replacing only `chi` does not accelerate or fully represent that path.

## 4. Continuum discontinuities and high-curvature regions

The audit found the following relevant sources:

- H I bound-free thresholds are generated by `COULX` (line 3199). In the tested 3500–9500 Å interval the important edges are 3647.0552455 Å and 8205.8743024 Å, using the same `2.997925e18` wavelength-frequency constant as `CONTOP`.
- H− is implemented at line 3359. Its bound-free threshold is near 16439 Å, outside this benchmark interval, but remains relevant to a general cache.
- He I/II and He− branches begin at lines 3714, 3860, and 3903. Most explicit photoionization thresholds are in the UV for this interval.
- Mg I PEACH table transitions are in `MG1OP` at line 4268. Optical knots/thresholds are 3756.6077790, 6549.6762111, 7234.2044446, and 7291.8238028 Å.
- Si I PEACH transitions are in `SI1OP` at line 4566. Optical knots/thresholds are 5379.9600305, 5625.0559846, 6260.4860021, 6349.3269354, and 6491.1039663 Å.
- Si II has additional table boundaries through the `LUKEOP` path (line 5866), including a 3900 Å boundary.
- Rayleigh and electron-scattering contributors (`HRAYOP`, `HERAOP`, `ELECOP`, and `H2RAOP`) are smooth functions in this range, but they still contribute separately to `sigma`.

The exact threshold conversion matters: an early prototype used a slightly different speed-of-light constant for Mg/Si and shifted nodes by roughly 0.0005–0.001 Å. Continuum results in this report were rerun using the literal `CONTOP` constant.

Naive interpolation across the H edges is invalid. Even with correct nodes on both sides, the Mg I region immediately redward of 3756.608 Å has enough curvature that endpoint insertion alone leaves a narrow percent-level error. This is a high-curvature problem, not a remaining cross-edge interval.

## 5. Benchmark setup

Four MARCS atmospheres were used:

| model | Teff | log g | [M/H] | vmic km/s |
|---|---:|---:|---:|---:|
| solar dwarf | 5777 | 4.44 | 0.0 | 1.0 |
| metal-poor dwarf | 6000 | 4.0 | -2.0 | 1.2 |
| cool metal-rich dwarf | 4250 | 4.5 | +0.3 | 1.0 |
| giant | 4500 | 2.0 | 0.0 | 1.5 |

Continuum evaluation covered 3500–9500 Å on a 0.5 Å offset grid plus 0.02 Å sampling around known edges and knots, for 16,040 wavelength points at all atmosphere depths. It tested 2, 1, 0.5, and 0.25 Å grids; linear-opacity and log-opacity interpolation; naive and edge-aware grids; and a 1 Å grid with additional local nodes.

The CDR benchmark used 378,154 valid lines extracted from `merged_3700-9500_hfs.lin`, line range 5045–5355 Å, a fixed 5000–5009 Å transfer grid, `accrt=1e-4`, and cumulative 0.2 Å-bin selection with threshold 0.001. Final CDR spectra used 5195–5205 Å at 0.05 Å sampling.

The independent final-spectrum benchmark used ±150 Å-padded line lists and 10 Å output windows at 3870, 4495, 5145, Na D 5885–5895, Hα 6560–6570, 7545, and Ca II 8545–8555 Å. It used all input lines plus SMElib's internal validity handling, so this isolates continuum interpolation from Python CDR selection changes.

The prototype lazily cached depth arrays at adjacent grid nodes. It was enabled only for the benchmark and instrumented query count, exact-call count, construction time, and interpolation time. It was removed from the native source after data collection.

## 6. Accuracy: continuum

Solar total-extinction errors over every wavelength/depth pair were:

| grid | interpolation | edge handling | median rel. | p90 | p99 | max | worst wavelength |
|---|---|---|---:|---:|---:|---:|---:|
| 2 Å | linear | naive | 1.69e-8 | 2.61e-4 | 8.36e-3 | 2.69 | 3647.05535 |
| 1 Å | linear | naive | 3.77e-9 | 5.66e-5 | 3.90e-3 | 5.39 | 3647.05535 |
| 2 Å | linear | edge-aware | 1.25e-8 | 1.95e-7 | 1.13e-3 | 2.42e-2 | 3756.6200 |
| 1 Å | linear | edge-aware | 2.84e-9 | 4.97e-8 | 1.11e-3 | 2.42e-2 | 3756.6200 |
| 1 Å | log | edge-aware | 4.06e-9 | 4.79e-8 | 1.11e-3 | 2.42e-2 | 3756.6200 |
| 0.5 Å | linear | edge-aware | 9.80e-10 | 1.00e-8 | 6.00e-4 | 2.42e-2 | 3756.6200 |
| 0.25 Å | linear | edge-aware | 3.09e-10 | 2.28e-9 | 2.38e-4 | 2.28e-2 | 3756.6200 |
| 1 Å | linear | local nodes | 2.39e-9 | 1.42e-8 | 6.13e-7 | 9.75e-3 | 3756.6200 |

For the 1 Å edge-aware linear grid, `(p99, max)` was:

- solar: `(1.11e-3, 2.42e-2)`;
- metal-poor dwarf: `(1.08e-5, 1.34e-4)`;
- cool metal-rich dwarf: `(7.12e-4, 2.13e-2)`;
- giant: `(1.49e-3, 4.48e-2)`.

Thus most wavelength/depth cells are extremely accurate, but a small number around opacity-table transitions dominate p99/max. Local nodes reduce p99 by roughly three orders of magnitude, yet the immediate Mg I red side still needs denser/adaptive treatment or exact fallback. Uniform 0.25 Å alone does not solve that local maximum.

Linear and log interpolation are effectively tied in continuum accuracy. Log interpolation costs more and is not valid for zero/non-positive component values, so linear interpolation is the better default.

## 7. Accuracy: ALMAX, central depth, and range

For 1 Å linear edge-aware interpolation, ALMAX relative p99 was between `1.09e-8` and `7.72e-8` for the four models. The largest individual ALMAX relative error was `4.54e-4` (cool metal-rich dwarf); across the tested spacings the largest was `7.90e-4`.

Every tested configuration produced **zero changed left/right physical validity ranges** among 378,154 lines in every model. Consequently all range absolute-error percentiles and maxima were zero.

Central-depth relative statistics require care because the exact calculation returns numerical zero for many ultra-weak lines while the approximate calculation can return values around `1e-10–1e-7`; dividing by exact zero creates meaningless values up to `1e293`. For the cool metal-rich model, where the distribution is well resolved, the 1 Å linear relative central-depth errors were median `1.09e-5`, p90 `6.81e-5`, and p99 `1.06e-3`. The largest zero-vs-nonzero absolute discrepancies seen in the stored worst-line list were about `1.3e-7`, far below the 0.001 selection budget. Production tests should report relative central-depth errors only above an explicit depth floor and absolute errors below it.

The 5045–5355 Å line set includes Mg b, strong Fe lines, and dense molecular lines. Selection changes at 1 Å were dominated by TiO in the cool model (27 TiO and one V I mask changes); other models changed only Co I, Cu I, MgH, or one TiO line. Hα, Na D, and Ca II were tested at the final-spectrum level below.

## 8. Line-selection stability

For 1 Å linear interpolation:

| model | exact selected | approximate selected | false positive | false negative | changed fraction |
|---|---:|---:|---:|---:|---:|
| solar dwarf | 8,911 | 8,911 | 1 | 1 | 5.29e-6 |
| metal-poor dwarf | 1,291 | 1,290 | 1 | 2 | 7.93e-6 |
| cool metal-rich dwarf | 335,587 | 335,591 | 16 | 12 | 7.40e-5 |
| giant | 17,110 | 17,111 | 1 | 0 | 2.64e-6 |

Across all four models this is 19 false positives and 15 false negatives among 1,512,616 line decisions. At 0.5 Å it falls to 8 false positives and 5 false negatives.

These changes are rare, but they are not described correctly as “individual depths within ±x% of 0.001.” The selector orders the weakest lines inside each 0.2 Å bin and drops them until their **cumulative** depth reaches 0.001. It is a rank/cumulative-boundary problem.

## 9. Final-spectrum accuracy

### CDR + selection + synthesis

In the 5195–5205 Å CDR test, the largest 1 Å linear total spectrum difference was `7.24e-6` with RMS `6.64e-7`, both in the cool metal-rich model. Re-synthesizing with exact continuum but the approximate selected mask gives the same difference, so this particular error is selection-driven rather than a direct continuum-interpolation error. Other models were at or below `3.1e-9` max.

At 0.5 Å linear the worst four-model result was `3.58e-10` max and `1.69e-10` RMS in this window.

### Independent broad-window synthesis

Across 16 model/window cases, the global worst 1 Å linear result was the giant at 3874.45 Å:

- max `|ΔF_norm| = 3.55e-6`;
- RMS `= 5.51e-7`;
- p99 `= 2.84e-6`.

For 0.5 Å linear, the same blue region remained worst but improved to max `3.95e-7` and RMS `4.49e-8`.

Representative 1 Å linear maxima were:

- solar 3870–3880 Å crowded blue region: `1.59e-6`;
- solar Fe-rich 5145–5155 Å: `1.52e-9`;
- solar Na D 5885–5895 Å: `1.11e-9`;
- Hα 6560–6570 Å across four models: at most `1.57e-9`;
- Ca II 8545–8555 Å across four models: at most `1.23e-9`;
- solar red 7545–7555 Å: `6.56e-10`.

No broad systematic normalized-flux offset was detected in these windows. The largest errors are localized in the crowded/high-curvature blue region. A direct synthesis window straddling 3756.608 Å was not run with the corrected edge prototype, so that narrow failure region remains a required production regression.

The measured spectrum error is much smaller than the previously observed validity-range approximation difference (`~3e-4–8e-4` max): about two orders of magnitude smaller at 1 Å in the worst tested window, and roughly three orders smaller at 0.5 Å.

## 10. Runtime and `CONTOP` call-count reduction

Current exact CDR timings after removing the redundant outer `CentralDepth` call were:

| model | exact total s | exact continuum queries |
|---|---:|---:|
| solar dwarf | 90.80 | 1,138,078 |
| metal-poor dwarf | 92.52 | 1,134,806 |
| cool metal-rich dwarf | 100.57 | 1,144,374 |
| giant | 94.80 | 1,138,095 |

For a 1 Å linear cache:

- total CDR time: 3.89–4.23 s;
- speedup: 21.9–24.1×;
- exact continuum evaluations: 634–681;
- resident nodes for this 310 Å line-list interval: 311;
- grid construction: 0.053–0.060 s;
- measured interpolation loop: 0.118–0.125 s;
- `Transf`: 1.36–1.69 s;
- `CentralDepth`: 2.32–2.38 s.

The cache therefore cuts exact continuum evaluations by roughly 1,700×. Interpolation arithmetic is small, although map lookup, line loops, and transfer work leave a total floor around four seconds.

Independent synthesis windows showed 16.2–33.7× speedup at 1 Å. For example, solar Na D went from 53.30 s and 703,737 exact evaluations to 1.72 s and 326 exact evaluations.

Aggregate four-model CDR results for linear edge-aware interpolation are:

|---|---:|---:|---:|---:|---:|---:|

Because exact-node construction is already tiny, 0.5 and 0.25 Å cost almost no wall-time in this prototype. However, memory and lookup costs will matter for a full 3500–9500 Å cache with separate component arrays. A 1 Å base is adequate away from edges; 0.5 Å is a useful conservative option but still does not by itself cure the Mg I local maximum.

## 12. Threshold-refinement experiment

The requested ±10%, ±20%, and ±30% raw-depth refinements were tested. For the 1 Å cache, exact recomputation counts ranged from:

- solar: 357 / 696 / 1,070 lines;
- metal-poor dwarf: 60 / 146 / 217;
- cool metal-rich dwarf: 9,281 / 18,546 / 28,894;
- giant: 410 / 865 / 1,409.

None of these changed the selection mismatches. This is expected after inspecting the selector: 0.001 is a cumulative discard budget per bin, not a per-line cutoff. Recomputing lines whose individual central depth lies near 0.001 does not necessarily touch the lines that straddle the sorted cumulative boundary.

A correct two-tier strategy must identify unstable bins and exactly recompute either:

1. lines near the cumulative cut rank, including enough weaker lines to bound the prefix-sum error; or
2. every line in a bin whose approximate cumulative sum is within a safety margin of the cut.

The simple ±10/20/30% individual-line rule is a no-go for this selector.

## 13. Known failure regions and limitations

- Naive grids catastrophically interpolate across H I edges; edge awareness is mandatory.
- The immediate red side of Mg I 3756.608 Å remains steep. Forced endpoints reduce the affected region but do not guarantee max-error control.
- The explicit edge inventory should be generated from, or kept next to, the opacity-source constants. A duplicated hand-maintained wavelength list is error-prone.
- Relative central-depth maxima for exact-zero ultra-weak lines are not meaningful; future reporting needs an absolute-error floor.
- The scattering-source mode was audited but not benchmarked end to end.
- The corrected 3756.608 Å edge must receive a direct spectrum regression before enabling the cache by default.
- Equivalent widths were not separately measured; normalized-flux residuals are stored and can support a later line-by-line EW study.

## 14. Recommended production design

1. Add a per-SMElib-state continuum cache, invalidated by the same model/abundance/EOS/opacity mutations that invalidate line opacity.
2. Cache depth arrays for `kappa`, `sigma`, and `chi`; do not cache only a scalar or only total extinction if scattering mode is supported.
3. Use linear interpolation in physical opacity/component values. It is as accurate as log interpolation here and faster/safer around zeros.
4. Use a 1 Å base grid.
5. Split interpolation intervals at all exact source-code thresholds and PEACH table boundaries.
6. Around high-curvature regions, use adaptive midpoint-error refinement or exact-query guard bands. Do not rely only on one node on each side.
7. For CDR selection, refine unstable cumulative bins rather than individual lines near 0.001.
8. Keep an exact mode and expose/cache statistics during rollout.
9. Add regression cases at H I 3647/8206 Å, Mg I 3756.608 Å, Si/Mg optical knots, crowded blue molecular spectra, Na D, Hα, Mg b, and Ca II.
10. Integrate the cache with the thread-safety/state-ownership design; do not introduce an unprotected global map.

## 15. Go / no-go conclusion

**Go for a formal implementation behind an opt-in/experimental switch. Do not make the simple uniform cache the default yet.**

The performance case is strong: roughly 22–24× faster full CDR and 16–34× faster synthesis, with a 1,700× reduction in exact continuum evaluations. The tested final-spectrum accuracy is comfortably better than `1e-4`, and line-range stability is perfect in this matrix.

The remaining blocker to making it the default is narrowly scoped: complete edge/high-curvature handling, especially a corrected direct spectrum regression around 3756.608 Å, plus correct component caching for scattering mode and state/thread-safe invalidation.

**Recommendation:** implement an edge-aware 1 Å linear continuum-component cache with adaptive/exact guard regions, and use cumulative-bin-aware exact refinement for ambiguous line-selection bins. Retain 0.5 Å as a conservative configuration, not as a substitute for edge handling.
